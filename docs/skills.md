# 技能

从侧栏「系统功能 → 技能」进入管理页。可以创建技能，或选择一个包含 `SKILL.md` 的本地文件夹导入。

技能文件示例：

```markdown
---
name: learning-coach
description: 学习新概念时，通过小例子、图解建议和练习帮助理解。
---

先确认学习目标，再用一个最小例子解释概念，最后给一道可验证的练习。
如果需要执行代码，先根据当前运行能力选择工具，执行后再报告结果。
```

导入保留原文件位置，外部修改会在下次使用时重新读取。「移除注册」不删除源文件。应用内创建的技能保存在应用数据目录的 `skills` 下。编辑现有技能会更新原 `SKILL.md`，保存旧版本到应用数据目录的 `skill-backups`；检测到外部修改时需重新加载后再保存。名称保持稳定，可以编辑用途和正文。

聊天输入框的星形按钮可选择已启用技能，会在问题中插入 `$learning-coach`。也可以手动输入同样的引用。手动选择的正文可用于纯文本模型；模型无法读取参考文件或执行命令时，应说明这一限制并继续给出能完成的部分。

具备工具调用能力的路线可自动选择相关技能。模型先获得名称和用途，再通过 `skills.load` 读取说明、`skills.read_resource` 分段读取包内 UTF-8 文件。`references/`、`scripts/`、`assets/` 可放在包中；加载不会执行脚本。执行脚本仍使用现有终端及当前项目权限，二进制素材不能冒充文本参考文件。

模型也可通过 `skills.save` 创建技能，或使用 `skills.load` 返回的 `revision` 更新现有技能。更新必须提供 `expected_revision`；冲突会返回给模型处理，原文件不会被旧版本覆盖。保存计入当前任务的修改预算，调用结果保存在工具操作记录中。

可选配置 `agents/openai.yaml`：

```yaml
policy:
  allow_implicit_invocation: false
```

设为 `false` 后，该技能只能通过用户显式选择调用。禁用技能会阻止后续加载和模型更新。损坏或缺失的包会显示原因；模型收到可解释的失败反馈，仍可继续回答。

技能是任务指导，不能授予新的模型、文件、网络或终端权限。技能正文和参考内容受当前上下文与读取预算约束；较长内容会明确标记截断，并提供分段读取方式。

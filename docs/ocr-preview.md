# OCR 隔离预览版

## 运行与版本

当前发布为 0.15.0-ocr-preview.2，分支为 `codex/auto-ocr-preview`。程序名称为 `agent OCR Preview`，应用标识为 `io.github.zcchou.agent.ocrpreview`，数据库 schema 28，IPC 21。

首次安装时下载当前 release 的安装器和全部六个离线组件 ZIP，保存到同一目录后运行安装器。已安装 0.15.0-ocr-preview.1 时可使用对应增量包，解压后运行 `UPDATE.cmd` 并选择旧安装目录。Document Preview 使用独立增量包。适用基线、验证范围和回退方法见 [发布与更新说明](rag-workspace-release.md)。

预览版按独立应用标识保存设置和数据库。首次运行需要配置主模型及资料库辅助模型。模型文件允许在导入时选择，OCR 使用固定适配的本地 PP-StructureV3 模型包。

## 导入 PDF

1. 进入“模型”，分别配置检索模型与 OCR 模型。OCR 模型包位于安装目录的 `ocr-model-package`。
2. 进入“本地资料库”，创建资料库并打开详情。缺少模型时可先创建空资料库，再从设置前往配置。
3. 点击“导入文件”，确认文件及 OCR 模式后开始。原生文字解析后可以预览，OCR 完成后统一建立并发布检索索引。
4. 在“处理任务”中查看一个顶层导入任务及其阶段计数。处理失败时展开详情查看原因并继续处理。
5. 在“项目设置 → 资料与 RAG”或项目对话顶部添加一个或多个资料库。后续就绪更新自动用于新问答。
6. 在文档预览中查看 PDF 原页、解析正文、OCR 对照和版本历史。物理页码用于原页与正文定位。

仅提取已有文字模式记录图片区域的覆盖缺口。OCR 缺失或失败时进入需要处理状态，用户可重试、核对原页或显式接受不完整结果。机器解析版本的修订版默认为“未标注”，可在文档信息中补充来源与版本，并单独记录人工复核状态。

同一导入任务的初始快照与最终快照联动撤回。撤回会取消该任务的在途识别，并使相关证据失效。

## 运行配置

本次随包 OCR 组件采用 Paddle CPU 推理。默认自动选择设备，CPU 调度按可用内存和逻辑核心数量决定使用一或两个 worker。启用两个 worker 的初始门槛为至少 12 GiB 可用物理内存与八个逻辑核心。单 worker 使用四个推理线程、4 GiB 进程树内存上限，单请求超时为 360 秒。

PDF 按 200 DPI 渲染，并受两千万像素上限约束。页面方向检测后恢复原图坐标。PaddleX 3.7.2 表格分支在收到整页 OCR 结果时存在二次单元格识别器未初始化的问题，本版通过官方预测开关关闭该二次识别，使用整页 OCR 结果匹配表格结构。复杂表格的行列、单位和脚注仍需要核对。

本机实测 Paddle 原生权重加载对中文路径存在兼容问题，本次使用 ASCII 用户路径下的受管模型库。中文用户名和其他存储路径需要进一步验收。

## 离线运行组件构建

`tools/prepare_ocr_models.py` 从官方模型发布源准备带文件哈希的本地模型包。该步骤在打包机执行。

`tools/build_ocr_runtime.py` 通过固定 SHA-256 校验的 CPython 3.12.10 Windows x64 embedded archive、已安装的 `requirements-ocr-preview.lock` 依赖和本分支源码组装独立运行时，生成逐文件哈希清单。用户电脑通过随包文件运行 OCR。

完整性校验在首次启动 worker 前执行。当前界面的“组件可用”表示找到了可执行文件，校验失败会在实际加载时显示错误。

## 本轮范围与后续验收

本版提供自动 OCR、表格基础结构、缓存、机器识别快照、索引和原页对照。页面缓存会持久保存，重新导入相同原件可复用成功页。

以下项目继续保留为后续工作。

- 区域级人工编辑、修订与独立审阅数据库。
- 应用重启后自动重新调度中断任务。
- OCR CUDA 组件及 GPU 实机验收。
- 全量扫描件吞吐、持续双 worker 压力、磁盘容量和完整出网监测。
- 干净电脑上的安装器、WebView2 随包安装与升级验收。

本机 DO-160G 测试采用全部原生文字与物理第 31 页图片表格，测试结果见交付目录中的验收记录。整份 542 页的全部待识别页 OCR 单独验收。

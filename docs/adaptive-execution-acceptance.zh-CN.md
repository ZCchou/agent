# 0.16.0-preview.5 智能等待与恢复验收

## 行为与操作

本版为主模型加载、意图识别、附件解析、OCR、嵌入、重排序、模板审阅和生成统一记录阶段身份、活动及恢复状态。

- 默认智能等待，90 秒提示长任务，300 秒无进展进入诊断。已经建立的心跳通道连续 30 秒失联会触发诊断。
- 阶段有可验证进展时继续运行。通信、实际进展和资源活动分别记录，未知指标保持未知。
- 确认可恢复故障后最多自动恢复两次。新批次验证成功后清零连续恢复次数，恢复旧批次保留原计数。
- 连续恢复无进展时保留任务，任务卡提供继续等待、恢复当前阶段、调整配置和取消。已交付部分文字的生成提供“保留草稿并重新生成”。
- “系统功能 → 模型 → 运行与等待”调整新任务策略。任务卡中的操作作用于当前任务。
- 活动调用持有模型使用标记，空闲驻留从调用结束后计时。

格式纠正与技术恢复分别审计。每批最多三次已经取得输出、进入格式或证据校验的调用。确认的引擎或连接失败进入技术恢复，保留实际调用记录、错误、已接收文字和用量。未知中断保守计入格式预算。

## 恢复与数据

数据库 schema 32、IPC 25、设置 schema 20、构建身份 `schema32-agent-unified-v1`、worker 协议 v2，工具契约 v5。

重排检查点包含项目、资料变更序号、索引、片段及文本哈希、模型指纹、设备和分词配置。每批事务提交，恢复前校验身份。资料撤回及修订变化会使受影响结果失效。检查点按任务结束后的 30 天保留规则清理。

应用重启后活动任务显示已中断。点击恢复前核对模型、资料及原件身份。取消、完成与恢复通过事务状态转换确定终态。旧修订和旧尝试的事件被身份检查排除。

## 自动化证据

最终测试数量、构建身份及发行文件 SHA-256 以随发行提供的验收结果和清单为准。本机测试使用独立数据库和临时目录。

已核验的专项行为包括超过旧 90 秒和 300 秒时限的持续进展、只存活无进展的诊断、批次崩溃恢复、恢复次数上限、来源失效、部分输出保护、同根模型加载恢复、预加载收据关联和跨修订事件检查。

独立代码审查发现并修复了恢复旧审阅批次误清零次数、普通日志被误算为加载进展、加载中活进程被误判退出，以及独立加载任务缺少恢复入口四项问题。完整回归另检验上下文整理恢复与取消的兼容入口。

## 真实运行组件

新辅助推理组件使用已校验的 CUDA 依赖离线构建，Torch 2.8.0+cu128、CUDA 12.8、ONNX Runtime GPU 1.23.2。13,091 个文件逐项核验，45 个 Torch/ORT 原生文件与已验证来源一致。

冻结 worker 的十项测试覆盖 BGE/Qwen 嵌入及重排序的 CPU/CUDA 路线，以及 ONNX CPU/CUDA，收到 25 个带身份及序号的 v2 心跳。这些测试采用小型受控权重。冷 CPU BGE 36.123 秒，驻留调用 0.007 秒。

OCR 使用独立目录中的 CPython 3.12.10、Paddle 3.3.1、PaddleOCR 3.7.0 和 PaddleX 3.7.2。实际 OCR 模型包约 681 MB。一页 CPU 实测 75.828 秒，收到 14 个 v2 心跳，识别三处文字及其边界框，进程正常关闭。

## 升级与回退

本次辅助推理与 OCR 组件发生变化。从 preview.4 升级应下载本版完整安装器及发行页列出的全部分卷，保存到同一目录，退出应用后安装。更新器通过运行组件身份检查提示完整包入口。

完整包支持差异安装。校验一致的现有文件继续使用，仅暂存和替换新增或变化的文件。完整一致的旧分卷可按大小及 SHA-256 复用。程序小包面向运行组件身份匹配的安装。

升级前保留程序、数据库及配置备份。迁移失败时保留错误与备份，恢复原程序和对应数据版本后再处理。安装事务失败时先使用安装器恢复或修复入口，文件状态不确定时保留事务记录。

安装器尚无 Authenticode 签名，程序更新包和更新清单使用独立发布密钥签名。U 盘拷贝应包含安装器、全部分卷、校验清单及安装恢复说明。

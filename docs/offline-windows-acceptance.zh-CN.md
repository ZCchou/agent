## 已有实测证据

### 主模型与辅助模型

Qwen3-8B Q4_K_M 和 DeepSeek-R1-Distill-Qwen-7B Q4_K_M 已分别通过源码管理入口的 CPU、CUDA、Vulkan 加载与文本生成，共六组。上下文配置为 8,192 token。最初执行期间存在并行构建，这组记录用于功能核验，正式计时另行记录。

Qwen3 权重来自官方固定版本。DeepSeek GGUF 来自 bartowski 社区量化仓库，原模型、转换仓库、版本及文件哈希在资产来源清单中分别记录。

最终源码在其他构建和真实模型任务退出后，另行完成以下单请求计时。均通过受管入口校验、加载和串行生成，实际上下文为 8,192。问题为简短中文问候请求。

| 模型 | 后端 | 加载含校验，秒 | 首段可见文字，秒 | 请求总生成，秒 | 输出 token | 端到端 token/秒 |
| --- | --- | --- | --- | --- | --- | --- |
| DeepSeek 7B Q4_K_M | CPU | 56.07 | 28.66 | 31.83 | 123 | 3.86 |
| DeepSeek 7B Q4_K_M | CUDA，11 层 | 32.50 | 15.82 | 17.86 | 81 | 4.54 |
| DeepSeek 7B Q4_K_M | Vulkan，13 层 | 42.77 | 19.90 | 21.80 | 103 | 4.73 |

DeepSeek CUDA 首次在 256 token 输出预算下被不完整结果检查拒绝。原失败记录已保存，表中 CUDA 行为输出预算提高至 512 后的独立重试，其余行预算为 256。这反映单请求结果，采样和推理长度会变化。Qwen3 本次只输出三个 token，端到端值主要受首段延迟影响。计时包含 prefill 和可能的隐藏推理，不能据此比较持续解码吞吐或业务长答案速度。

六例首轮进程树 RSS 峰值约 7.33 GiB，private memory 峰值约 4.56 GiB，全显卡占用峰值 3,384 MiB。两次观察的非回环连接和采样错误列表均为空。

完整 Qwen3-Embedding-0.6B、Qwen3-Reranker-0.6B、BGE-M3 和 bge-reranker-v2-m3 已通过冻结辅助 worker 的 CPU 嵌入或相关性评分。BGE-M3 官方原始权重在构建缓存中经过 `weights_only` 读取后转换为 safetensors，转换记录和输入输出哈希已保存。应用导入入口拒绝 pickle 权重。

上述四份完整辅助模型的 CUDA 尝试均被当前 4 GiB 显存设备的资源预检拒绝。完整辅助模型 CUDA 推理仍待更大显存设备实测。

冻结 Core 已加载官方 Qwen3-1.7B Q8_0，使用 CUDA、23 层 GPU 卸载和 8,192 token 上下文，并通过原生工具调用探测。该模型在其官方 GGUF 仓库中提供 Q8_0，本次按实际文件记录量化类型。

### 联合业务链路

8B 主模型与完整 Qwen 辅助模型、8B 主模型与完整 BGE 辅助模型，以及 1.7B 主模型与完整 Qwen 辅助模型的联合尝试，均在当前设备发生提交内存不足或 CPU 分配失败。1.7B 组合的项目自动检索和必需 RAG Skill 两例均失败，错误为 `rag_model_error`。主模型成功加载不能代替联合业务通过。

最终 v6 Core 与官方 Qwen3-1.7B Q8_0、CPU INT8 ONNX BGE-M3、CPU INT8 ONNX bge-reranker-v2-m3 的联合测试已完成。项目默认问答和显式选择内置适航 Skill 两例均完成，并通过真实证据编号、版本和逐字摘录校验，保存为待复核草案，耗时分别为 100.64 秒和 180.79 秒。语料为一条虚构测试条款。这两例使用执行器预检索证据，模型未额外发起 `rag.search` 或 `rag.read` 工具调用。

本次联合进程树 RSS 峰值约 4.17 GiB，private memory 峰值约 5.76 GiB。全显卡占用峰值 3,320 MiB，包含桌面等其他显卡使用者。连接元数据采样未见非回环连接，采样错误为空。

另以最终 v6 Core、官方 Qwen3-8B Q4_K_M 和同两份 CPU INT8 包补测默认 CPU 路线，上下文同为 8,192。主模型加载及索引构建成功，项目问答和显式 Skill 两例均返回 `request_timeout`，耗时分别为 266.61 秒和 352.90 秒。该轮工具能力探测返回 `internal_error`，原始记录已保留。加载预检提示物理内存压力，联合进程树 RSS 峰值约 8.40 GiB，private memory 峰值约 7.08 GiB。本轮未完成该配置的业务验收，超时记录本身不足以单独确定全部性能成因。现有可重复通过的联合样例仍为上述 1.7B CUDA 与 CPU INT8 组合。

ONNX 转换包分别来自 `Xenova/bge-m3` 的 `4de13258303883538bd53b696b452bf8099f0858` 和 `onnx-community/bge-reranker-v2-m3-ONNX` 的 `6f5ff65298512715a1e669753bc754d2bc8f367b`。两个图均采用标准 ONNX 域，输入为 `input_ids` 和 `attention_mask`。嵌入图输出 1,024 维 hidden state，采用 CLS 池化和归一化；重排图输出 logits，由现有适配器应用 sigmoid。实际按固定文件哈希校验，最大输入长度配置为 8,192。

两份转换仓库均未提供独立 LICENSE 文件。嵌入转换卡声明 MIT，重排转换卡未声明许可证，上游 BAAI 模型声明 Apache-2.0。来源清单保留这些差异。模型权重作为验收输入单独存放。

同两份真实 INT8 ONNX 包还通过最终冻结辅助 worker 的 CPU、CUDA 四组单独推理。嵌入输出为 1,024 维单位向量，相关测试文本在两种设备下均排在无关文本前。重排相关/无关得分在 CPU 为 0.919385 / 0.000016323，在 CUDA 为 0.926346 / 0.000016369。四次 worker 均正常退出。CUDA 测试覆盖请求的 provider 校验及真实 session 推理，未采集每个算子的设备放置，部分不支持的算子可能由 CPU 执行。

### 官方参考数值对照

四份完整原始辅助模型和两份 INT8 包另行完成六项 CPU 对照，逐项启动独立进程，先取得冻结 worker 输出并关闭，再运行参考计算。参考使用固定 Hugging Face 内置类、FP32 和独立实现的官方池化及评分公式。为避开已复现的 Windows safetensors mmap 访问异常，参考仅在权重读取阶段复用经过校验的 owned-byte 读取器。模型前向及池化评分分别核对，全部访问采用本地文件。

| 原始模型 | 当前输入约定下最大数值差 |
| --- | --- |
| Qwen3-Embedding-0.6B | 1.49 × 10⁻⁸ |
| Qwen3-Reranker-0.6B | 5.22 × 10⁻⁸ |
| BGE-M3 | 1.49 × 10⁻⁸ |
| bge-reranker-v2-m3 | 2.27 × 10⁻⁸ |

四项均满足本次短文本 FP32 数学对照的 10⁻⁴ 容差。Qwen 重排的完整位置 logits 与只计算末位置 logits 最大差为 3.81 × 10⁻⁶。

Qwen 嵌入适配器当前使用 `Query: ` 后带一个空格的查询模板，官方固定版本示例为 `Query:` 后直接接问题。这会改变 token，本次向量坐标最大差为 0.0140094。表中该模型一行为统一当前输入约定后的数学对照，官方无空格主参考及其差异单独保留。此交付沿用当前固定适配约定。

INT8 BGE 嵌入与 FP32 的三个向量余弦为 0.9850、0.9867、0.9816，最大坐标差为 0.02664。INT8 重排与 FP32 最大得分差为 0.00618。两包 token 化均与 FP32 参考相符，所测相关/无关文本排序一致。这些短文本量化差异作为实测值保存，长文、企业语料和专业质量另行评估。

最终 Core 可执行文件的 SHA256 为 `95cda94410e331640cd96ff952f6072a9492a16db033e71b5f7480a1373d75c3`。原始结果文件名中的 v5 为验收目录沿用名称，联合测试实际运行上述 v6 Core，并复用源码身份不变的 v5 辅助组件。

使用实际冻结 Core 的公开 `rag.request` 入口，启用完整运行组件和模型校验。SQLite 中有 100,000 个片段，每条向量实际为 1,024 维、4,096 字节。

语料由十条虚构测试条款分别重复一万次组成。入库时，验收适配器对完全相同的文本复用真实计算结果，因此只对十个不同文档文本计算嵌入。索引发布、查询嵌入、授权范围内的完整向量扫描、候选重排和证据校验使用生产路径。本项覆盖容量和查询链路，企业法规检索质量与十万条不同文档的嵌入吞吐需要另外验证。

p50 和 p95 按十个请求的 nearest-rank 方法计算，p95 为本次最大值。查询包含反复组件及权重校验、worker 启动与模型切换加载开销，当前 CPU 路线耗时较长。索引构建时间来自首次成功发布的实验，随后查询阶段发现的模型切换原生崩溃已修复，保留了首轮失败记录。十次完整查询来自修复后的 v4 组件，v5 仅补充冻结解释器所需 SSL 数据资源，相关 worker、适配和依赖锁源码身份保持一致，最终安装产物另做抽样验证。

### 网络观察

容量测试按 0.1 秒间隔采样应用及子进程的 IPv4、IPv6 TCP/UDP 连接元数据，观察约 2,232 秒，采样中未发现非回环连接，采样错误列表为空。

轮询可能漏过短连接和失败的连接尝试。完整出网审计需要 ETW、抓包或等效方法，并在断网环境重复业务流程。

### 最终冻结解析组件

v5 Core 的实际 `--document-worker` 已分别解析合成 TXT、DOCX 和文本 PDF，返回 1、3、1 个片段，耗时约 3.56、3.21、4.43 秒。解析通过受管父进程启动，使用默认 1 GiB Job 内存限制。PDF 返回阅读顺序及表格结构待核对警告。安装后的同一路径仍需单独抽查。

## 外部环境验收状态

尚无干净 Windows 虚拟机、无 NVIDIA 驱动的 CPU-only 实机和足够显存的原始辅助模型 CUDA 验收设备。干净电脑断网安装、CPU-only 对完整 CUDA 随包组件的兼容性、四份原始 safetensors 辅助模型的 CUDA 推理，以及正式出网审计分别保留为待验收项。已通过的 INT8 ONNX CUDA 两模型单独记录。

当前缺少发行签名私钥，交付产物采用未签名的本地核验状态。正式公开发行需补充签名和干净环境验收记录。用户端通过本地文件导入模型权重，运行组件及必要微软依赖随离线交付包提供。

## 实施取舍记录

| 取舍 | 原因及影响 |
| --- | --- |
| 使用既有独立检出和 `codex/managed-local-runtime` 分支 | 原生 worktree 创建曾超时，既有基线干净。若隔离不足，需要重新整理工作区和验证关联改动 |
| 实施任务串行，独立 Core 整合和只读审查分开进行 | 控制共享文件冲突。接口判断失误会产生集成返工 |
| 大型缓存、模型和临时文件使用 F 盘 | C 盘初始可用空间约 12.5 GiB。F 盘承担较大的缓存占用和深目录路径成本 |
| 十万片段使用重复合成语料，并仅在验收入库阶段复用同文嵌入 | 在当前设备完成容量和生产查询验证。企业检索质量和不同文本入库吞吐仍需实测 |
| 冻结源码审查与构建验收交错进行 | 减少等待，后续实际发现的界面、解析及安装缺陷均补充修复和定向复审。源码变化会使关联产物重建 |
| 进度细分、诊断 JSON 展示和 CUDA 许可证缓存参数保留为次要待办 | 现有页面及准备输入可完成导入和构建。操作体验和新构建机准备过程仍有改进空间 |
| 按当前功能范围评估离线策略和恢复机制 | 回环与权限在应用入口及受管进程执行，用户明确操作和恢复副本按既有设计保留。系统级环境及未取得的设备验证分别记录 |
| 保留 Qwen 嵌入查询模板中的单个空格 | 当前固定约定的数学对照通过。与官方示例的 token 和向量差异已量化，后续约定变化需要版本记录和验证 |
| 实际安装编译失败后重新打开第 5 阶段的定向修复 | 修复 MUI 回调冲突和 Tauri 打包后 Host 标记变更，补充真实模板测试及哈希复审，增加了发行验证时间 |
| 单 EXE 长路径失败后采用完整离线 ZIP | 保留原失败证据和全部载荷。用户须完整解压，交付体积与逐文件安装校验开销相应保留 |

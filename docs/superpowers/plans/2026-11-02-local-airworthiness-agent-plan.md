# agent：仅本地模型适航审定助手改造计划

> 版本：v0.1，方案草案。日期：2026-11-02。本文用于评审和安排实施，尚未实施任何所述新功能。
>
> 执行说明：后续实施使用 `superpowers:executing-plans`，按里程碑逐项验证。本文上传不代表业务范围、硬件配置和验收指标已获业务方确认。

**Goal：** 将现有 agent 改造为仅使用本地模型、支持适航审定 RAG 和专业 Skill、能够追溯证据与人工复核过程的桌面应用。

**Architecture：** 保留 React/Tauri/Rust Host/Python Core；在 Host 与 Core 双层实施本地运行策略，新增版本化资料库、混合检索、证据校验和审定工作流。生成模型、Embedding、重排序及 OCR 均在本地运行，不回退到公网服务。

**Tech Stack：** 现有 TypeScript、React、Tauri 2、Rust、Python、SQLite；首选复用 Ollama，候选增加本机兼容接口；文档解析、中文检索和向量后端在 P0 完成离线 Windows 验证后锁定。

**Spec：** 本文第 1—9 节为目标设计，第 10—13 节为实施、验收及待确认事项。基线为 `main` 提交 `b7bc992114b771bb9387b25013f06ee885d7240a`。

“适航审定大模型项目”在首期体现为专业应用系统，不预设自研基础模型。模型微调需在收集经过授权且经专家标注的评测数据、证明 RAG/Skill 不能解决的问题之后单独立项。

**输出边界：** 系统提供资料查找、条款引用、符合性分析草案和审查线索；最终审定结论、符合性判断和签署由有相应职责的人员完成。不得把模型生成的“符合”直接保存为正式批准状态。

## 4. “仅本地”的可验证定义

### 4.1 全链路范围

- 本地生成、Embedding、重排序、OCR、文档解析、检索、日志与导出；不能只限制聊天生成模型。
- 禁止云模型、托管搜索、原生联网搜索、远程图片加载、遥测和崩溃上传；运行时不自动下载模型、分词器、字体或解析资源。
- 模型与软件依赖可在准备阶段经授权获取，随后以带版本、许可证和哈希的离线包转入；运行态与安装准备态分开验收。
- 模型服务故障、能力不足或向量化失败时明确报错，允许用户选择另一已安装本地模型；不得切换到云服务。
- 回环接口并不证明服务在本地推理。受支持部署必须记录运行引擎、模型文件清单和服务启动配置，并将模型服务进程纳入出网验证。

### 4.2 实施约束

1. 新增 `local_strict` 部署策略。Host 保存并校验配置，Core 在实际发起每一次模型/Embedding/重排序调用前再次校验；前端不得通过 IPC 绕过。
2. 首期只允许显式配置的数值回环地址和端口；拒绝公网、内网非回环、带用户信息、歧义 IP、非 HTTP(S) 协议和重定向。IPv4/IPv6 分别测试。
3. HTTP 客户端禁用环境代理继承和重定向；不把 `is_local`、模型服务商名称或“本地优先”路由当作授权依据。清理云服务预设和云端计费/预算入口。
4. 导入旧设置时先备份，禁用非本地配置并提示用户；保留旧数据用于回滚，不静默删除 API 密钥，不在新运行时读取云密钥。
5. 禁用任意终端和 Skill 自带脚本自动执行；仅开放实现过权限检查的结构化业务工具。需要脚本时另行设计受限执行器，不能声称设置工作目录就是系统沙箱。
6. 对应用、解析/OCR 子进程和模型服务做部署级出网限制及实测。应用策略不能证明用户启动的其他程序从未联网；无出网承诺只覆盖受支持部署的明确进程集合。

若后续允许单位内网，需单独增加 `managed_lan` 模式、固定端点白名单、认证/证书、项目数据授权和服务端不转发证明；不得直接放宽 `local_strict`。

## 5. 适航资料与版本治理

### 5.1 首期资料类型

优先支持有文本层的 PDF、DOCX、TXT、Markdown；扫描 PDF 通过本地 OCR 入库。表格和扫描质量在 P0 取样验证，复杂图纸和手写件不承诺自动理解。首期符合性矩阵导出 CSV/Markdown；XLSX、DOCX 的正式版式导出列入后续增强。

资料分类采用可配置标签：规章、咨询/指导材料、标准、项目审定基础、符合性方法、计划/报告、问题记录。分类只是元数据，不自动决定法律效力或项目适用性。

示例体系可包含 CAAC，并在需要时扩展 FAA/EASA；具体规章部、修订状态、审定基础、专用条件、豁免或等效安全判断，均需项目人员确认。本文不宣称任何示例资料当前有效或必然适用于某个机型。

### 5.2 最小数据对象

| 对象 | 关键字段与约束 |
| --- | --- |
| `KnowledgeSpace` | `id, scope(public_reference/project), project_id, access_policy`；公共参考库与项目库分开授权 |
| `Document` | `id, space_id, title, issuer, jurisdiction, document_number, rights_note`；记录资料来源与使用权限 |
| `DocumentVersion` | `id, document_id, revision_label, effective_from/to, verification_state, verified_by, source_sha256, parser_version, status`；已发布版本不可原地覆盖 |
| `Clause` | `id, document_version_id, clause_number, heading_path, parent_id, text, text_hash`；条款号以版本限定，不单独充当主键 |
| `Chunk` | `id, version_id, clause_id, physical_page, printed_page_label, bounding_box, raw_text, normalized_text, offset_map, hash`；展示原文与检索规范化文本分离 |
| `IndexRevision` | `id, space_id, document_set_hash, embedding_model_digest, dimensions, tokenizer_version, chunker_version, state`；索引不是证据原件 |
| `CertificationBasis` | `id, project_id, revision, jurisdiction, product_tags, selected_document_versions, applicability_notes, confirmed_by`；明确支持“未确认”状态 |
| `EvidenceSnapshot` | `id, run_id, index_revision, source_versions, chunk_hashes, quote_spans, retrieval_config, model_digest`；回答可追溯至当时版本 |
| `ReviewArtifact` | `id, project_id, type, content_revision, evidence_snapshot_id, skill_revision, status, reviewer_note`；AI 草案与人工复核分离 |

时间字段允许未知，文件时间戳和下载时间不能冒充生效日期。规章“当前版本”与项目冻结的“适用版本”分别展示；旧版可用于明确指定的历史问题，不能混入默认当前检索。

### 5.3 入库流水线

`授权选择文件 → 复制到应用管理的内容寻址存储 → 哈希/去重 → 解析或 OCR → 条款及页码标注 → 人工确认元数据 → 构建候选索引 → 校验 → 原子发布索引版本`。

- 解析任务异步、可取消、可恢复；限制文件大小、页数、解压比例、内存和用时。拒绝加密未解锁文档、损坏文件和不支持格式；不执行 Office 宏、PDF 脚本或嵌入对象。
- 页码同时记录物理页与印刷标签。表格保留标题、表头、单位、脚注和跨页关系；条款切块不拆掉否定、例外及适用条件。跨条款引用保留关系。
- OCR 置信度仅用于提示复核，不当作正确率保证；低质量页可标记“禁止作为回答证据”。无法可靠定位的 DOCX 段落用标题/段落定位，不编造页码。
- 新版本和新 Embedding 模型构建新索引；成功后再切换。失败不损坏可用旧索引。删除资料立即撤销可检索权限；关联既有回答标记“来源已撤回”，受保留策略约束处理快照，不继续展示无权查看的原文。

## 6. 本地 RAG 设计

### 6.1 模型与检索后端选择

- **生成：** 首选已有 Ollama 适配；本机兼容接口作为可选适配，不需要接入公网 API。具体模型依据中文适航术语、上下文、结构化输出和硬件实测选择，不按参数量直接承诺效果。
- **Embedding：** 本地中英双语模型；BGE-M3 可作为对比候选，但不预先指定为最终依赖。检查权重与依赖许可证、内存、向量维度、离线加载和打包方式。
- **重排序：** 本地可选模型；低配模式可关闭，但需要分别标记、评测，不把关闭后的性能当作相同配置。
- **索引：** SQLite 管理元数据和 FTS5；中文采用显式版本化的分词/二元词项字段，不能假设 FTS5 默认分词已解决中文检索。向量存储通过接口隔离。
- **向量实现决策：** P0 比较本地精确向量检索基线与 Windows 可打包的 `sqlite-vec` 等后端；通过离线构建、取消/恢复、速度和许可验证后记录 ADR 并锁定一个首期后端。未通过时先交付明确标记的词法基线，不宣称完成向量 RAG。

### 6.2 查询链路

1. 读取项目授权和已确认的审定基础；范围未确定时要求选择资料集，或仅给通用资料检索结果，不推断机型适用性。
2. 规范化术语、缩写、条款号和中英文查询；保留用户原问题及改写记录。精确条款号检索先于语义近似。
3. 对已授权资料、选定版本与状态预过滤，再进行词法和向量检索；不能只在最终答案中删除越权内容。
4. 使用 RRF 等可解释融合策略，必要时本地重排序；补充条款父标题、定义、例外和表格上下文。固定候选数量、证据预算和去重规则，参数在开发集调优。
5. 将证据包注入现有 `ContextEngineService` 的检索区，作为不可信资料内容，不作为系统指令。记录检索配置和索引版本。
6. 本地生成结构化草案；程序校验引用 ID、版本、原文片段和授权，未通过的主张不作为“有依据结论”展示。
7. 返回正文、出处、适用条件、缺口和复核提示；支持打开对应原文位置。审定工作流中的关键生成阶段必须有证据，不依赖模型自行决定是否调用 RAG。

### 6.3 引用、拒答和冲突

引用由程序根据 `evidence_id` 解析，模型不能凭文本构造来源。格式至少包含资料名称、版本、条款号或段落、页码/定位和短原文；区分原文、模型解释与人工补充。

`AnswerDraft` 建议契约：`status(answered/insufficient_evidence/conflicting_evidence), claims[{text,evidence_ids}], assumptions, missing_inputs, review_required`。`CitationValidator` 校验存在性、授权、片段哈希和版本一致性；“引用存在”不等于“逻辑支持”，后者通过专家评测与复核处理。

没有足够证据时返回资料缺口和下一步，不补写看似真实的条款号。版本冲突、适用范围未确认、OCR 关键数字不可靠时必须显式提示；不得通过模型记忆替代缺失的项目资料。

## 7. 适航 Skill 体系

### 7.1 首期四类技能

| 技能 ID | 输入 | 产物 | 关键约束 |
| --- | --- | --- | --- |
| `airworthiness-clause-qa` | 问题、资料集、范围/版本 | 条款问答草案与证据 | 没有有效证据不输出确定的条款结论 |
| `certification-basis-checklist` | 项目概况、候选资料和人员指定范围 | 审定基础信息清单、待确认事项 | 不自动认定机型分类或正式适用规章 |
| `compliance-matrix-draft` | 已确认基础、条款、已有符合性资料 | 矩阵草案：条款、要求、方法建议、证据、缺口、责任人待填 | 符合性方法为建议；不得把“已找到文档”当作“已符合” |
| `review-issue-draft` | 选定报告、审查问题、引用 | 审查意见/问题单草案 | 结论、建议与事实依据分栏；保留人工修改和复核记录 |

首期“报告审查”只针对用户选定范围的证据支持与缺口检查，不承诺自动完成整机适航符合性审查。

### 7.2 技能包与调度

复用 `SKILL.md + references/ + assets/`，新增版本化 manifest：`skill_id, revision, input_schema, output_schema, required_tools, required_evidence, applicability_tags, min_runtime_version`。具体存储方式在实现时兼容现有 YAML 解析，不把示例元数据当作当前已经支持的字段。

- Skill 规定步骤、输入输出和证据要求；法规事实来自版本化 RAG，不能长期固化在提示词里冒充当前有效条款。
- 由确定性工作流负责“检查输入 → 检索 → 生成 → 引用校验 → 保存草案”。有工具能力的模型可补充检索，无工具能力的文本模型仍能执行受控流程。
- Skill 不能扩大资料权限、启用网络或执行任意脚本；禁用后下一步执行立即受阻。模型不得自行修改发布中的专业技能；编辑、复核、发布与运行版本分离。
- 每次运行记录 Skill 版本、输入摘要、模型清单、索引版本、证据与人工动作。资料及 Skill 中的恶意指令不能覆盖系统策略。

## 8. 产品界面与业务流程

主入口调整为：**审定工作台、项目、资料库、本地模型、专业技能、审计/复核、设置与诊断**。未完成能力不展示为可用功能。

- **首次启动：** 选择本地服务 → 检测模型及资源 → 离线自检 → 导入示例资料；不出现云端注册或 API Key 引导。
- **资料库：** 展示来源、版本、生效状态的核验情况、解析质量、索引状态；支持暂停、重试、版本切换和撤回。
- **项目：** 保存产品标签、资料授权及审定基础；范围未确定可建项目，但显著显示“适用性未确认”。
- **问答：** 选择项目/资料范围和 Skill → 提问 → 展示回答、原文证据与缺口 → 打开原文 → 人工确认或记录意见。
- **工作成果：** 草案、待复核、已复核、作废分开；“已复核”只是应用内人工动作记录，不冒充审定机关签署。离线单用户版不提供未经验证的多人身份与电子签名保证。
- **诊断：** 显示模型文件/服务、索引版本、存储占用、离线策略和最近失败原因；不显示密钥或私有原文日志。

## 9. 数据与开源交付边界

公共仓库只提交代码、计划、模板和自制/可再分发的合成样例。实际项目报告、单位内部资料、付费标准、模型权重、向量库和审计数据库不随代码上传。

资料导入记录 `rights_note` 和来源；可检索不等于可再分发。正式标准、行业文档及模型各自适用的许可证需单独核验；本仓库 MIT 不覆盖这些内容。本文不提供对特定法规版本的法律有效性背书。

本地数据库、证据原件和索引需有备份、恢复与删除策略；不得宣称整个应用数据目录已加密。先核查现有恢复点加密的实际覆盖范围，再决定全库/文件加密与 OS 账户边界。

## 10. 全局约束与评审重点

### Global Constraints

- `local_strict`：生成、Embedding、重排序、OCR 全部本地，运行时无公网回退和自动下载。
- 适航范围未确认；文档分类、机型标签、规章体系和适用版本均可配置。
- AI 产物默认草案；正式适用性、符合性和审定结论由相应人员确认。
- 资料授权在检索、引用展开、缓存和导出各层生效；撤销授权立即影响后续访问。
- 保留现有项目数据；数据库/设置/IPC 变更必须备份、版本迁移及兼容性验证。
- 先实现证据闭环，后扩展任务类型；不将微调、多用户服务、任意脚本执行纳入首期。

### Review Focus

1. 公网回退、代理和重定向绕过本地策略：P1 以真实客户端和网络观测验证，不能只检查 UI。
2. 同条款不同修订、未知生效状态或冻结基础冲突：P2/P3 保留来源身份，测试不混用版本。
3. 中文编号、OCR 数字、表格脚注和多页引用错误：P2 的解析金标与 P3 的引用校验覆盖。
4. 不同项目、撤回资料、旧快照和索引重建间的权限泄漏：P2/P3 覆盖读取、缓存和恢复。
5. 无原生工具能力模型或恶意 Skill/文档绕过流程：P4 用确定性编排和对抗样例验证。

## 12. 验收建议、依赖关系与估算

### 12.1 建议门槛（P0 经业务方确认后冻结）

| 项目 | 建议验收方式 |
| --- | --- |
| 本地边界 | 支持的完整任务链无公网请求；无云回退；未批准端点、代理/重定向绕过及运行时下载均被阻断 |
| 权限与引用完整性 | 工程测试中越权读取和伪造/失效引用被 100% 拒绝；这不是对所有未来攻击的绝对保证 |
| 检索召回 | 可回答金标题的相关证据 Recall@10 ≥ 90%；固定语料、版本和相关性标注 |
| 答案依据 | 专家逐主张核验支持率 ≥ 95%；无伪造条款号或无依据的正式合格结论；严重错误独立列出并阻止验收 |
| 拒答/冲突 | 对无依据及冲突测试题正确提示比例 ≥ 95%；同时报告可回答题被错误拒答的比例 |
| 解析定位 | 金标集所有被采用引用可定位到正确原文；低质量页和不可定位片段不进入合格证据集 |
| Skill 工作流 | 四类技能均能在无公网、无任意脚本和非工具型本地模型下完成基本受控流程，输出通过契约校验 |
| 性能 | 在 P0 指定硬件、约 10 万块基准库及固定并发下，预热检索 p95 目标 ≤ 3 秒；生成速度/首字延迟按实测协商，不在未知硬件上作保证 |
| 可复现/恢复 | 固定模型与索引版本可追溯；取消、崩溃恢复、索引切换和升级数据保留测试通过；不要求随机生成文本逐字一致 |

### 12.2 顺序与工作量

主依赖：`P0 → P1 → P2 → P3 → P4 → P5 → P6`。P2/P3 接口确认后，可先制作 UI 骨架和合成评测数据，但不能在证据与授权未完成时宣称业务闭环。

粗估 36—58 工程人日，单名全职工程师约 8—12 个工作周，另需适航专家、测试与部署人员投入。该数字不是交付承诺；不含资料整理/授权等待、硬件采购、复杂 OCR 调优、微调、多人平台和真实业务验收排期。P0 后重新估算。

现有 CI 作为基线保留，并增加本地策略、知识库、RAG、专业 Skill、迁移及离线打包检查。继承的测试间歇失败、低危依赖告警和大包告警需进入任务清单，不能从重跑通过推断已根治。

## 13. 待确认事项与下一步

1. **业务范围：** 审定环节、机型/产品、规章体系、专业方向、主要资料和最终使用者；当前允许暂不确定。

# 离线包去重与 preview.2 发布计划

目标为发布 `0.16.0-preview.2`，包含已通过本机迁移验证的 SQLite 修复。延续 Windows 11 x64 完整离线交付，保留 CPU、CUDA、Vulkan、ONNX、safetensors、OCR 和 Office 能力。

## 实施与验证

- [ ] 在 `tools/rag_runtime_assets.py` 的现有裁剪入口合并重复 DLL。保留 `torch/lib` 的上游布局，只有根目录同名 DLL 的大小和 SHA-256 完全相同才删除根副本。链接和不同内容的文件保持拒绝或保留策略，记录规范位置及节省字节。
- [ ] 添加红绿回归，覆盖精确重复、同名不同内容、链接拒绝和重复运行。离线 ZIP 压缩级别改为 6，并验证真实压缩/解压完整性。
- [ ] 在独立 F 盘暂存目录优化现有已验证运行组件，重建文件清单。运行真实 ONNX 嵌入/重排 CPU、CUDA，以及原始权重四个适配器的小模型 CPU、CUDA 测试。
- [ ] 更新应用、Core、Cargo 与依赖锁中的版本，构建 release Host/Core/更新辅助程序。执行 Core、前端、Rust、严格 Clippy 和发行工具回归。
- [ ] 生成完整离线安装器、分卷、签名程序更新包、校验清单和当前安装说明。程序更新包使用已有 preview.1 运行组件清单，以便现有安装接收应用修复。完整安装包使用去重后的组件清单，两个交付的程序文件相同。
- [ ] 实际安装、重启、冻结解析、组件验证及卸载测试，在隔离目录执行并恢复安装注册项。记录最终大小与旧版差异。
- [ ] 完成独立全分支审查，修复重要问题。推送源码并创建 PR，上传和核对 GitHub 全部资产，发布预览版。签名更新清单通过 PR 合入 main 后，从实际公开地址验签。

## 边界与记录

模型权重继续由用户从本地导入，OCR 权重随包交付。主推理和 OCR/Office 组件沿用各自固定版本。当前正在使用的本机应用与用户资料独立保留。

DLL 去重以真实加载测试为准。若移除根副本导致加载失败，将修正加载路径或保留必要副本，并记录实测节省。程序更新继续保留现有运行组件，完整安装可采用优化后的布局。安装器 Authenticode 状态及干净机、企业资料质量等验收边界随发布说明列出。

# 本地任务编排一致性修复计划

> 执行时使用 superpowers:executing-plans，逐项完成缺陷复现、修改和回归。

**目标** 使任务完成判定、计划修订、证据分流、后台恢复和主模型故障恢复遵循同一任务要求。

**架构** 复用现有业务计划、模型工具循环、执行监控、文件发布和调用审计。原始用户要求、可修订执行计划和已确认执行结果分别保存并相互关联。任务恢复继续当前未完成阶段，已确认的工具结果进入恢复后的上下文。

**技术栈** Python Core、SQLite、React/TypeScript、Rust/Tauri、现有本地推理组件。

**依据** 2026-11-15 对 0.17.0-preview.2 的设计审查，已复现完成判定、范围修订和规则分流问题，已核对启动恢复及主模型恢复调用链。

## 范围与交付安排

- 首选在现有架构中修复五项冲突，复用既有数据和任务身份。
- 修复版使用 0.17.0-preview.3，独立保存候选包身份和校验值。
- 当前 preview.2 的续传继续指向现有草稿发行，修复包建立自己的发行资产。
- 业务使用本地模型与工具，联网操作沿用独立更新器路线。
- 完成专业验收后公开发布，PR 合并沿用单独确认流程。
- 数据库新增目标要求记录时升级 schema35，IPC28，构建身份 schema35-agent-unified-v1。设置20、worker v2沿用。
- 用户工具新增可选目标要求字段后升级工具契约v7，同步Core、Host、前端及构建检查。旧计划更新参数保持可读。

## 核心数据与判定

在 execution_wait_tasks 根任务下新增 task_goal_requirements，保存要求修订、用户请求修订、来源身份、必需操作、处理范围、交付格式及用户确认来源。

首次主模型动作一并提出目标要求与执行动作，执行器将其与原始请求、明确范围、附件身份及文件要求核对。用户尚未明确的信息可在读取材料后确定，真正影响结果的缺项沿用澄清弹窗。执行计划的修改独立于用户要求的变更。

完成检查读取目标要求和实际覆盖、工具、文件记录。必需审阅位置需要审阅结果，读取元数据无法满足该项要求。请求交付文件时核对实际发布路径、格式、哈希和发布状态。缺少必需范围或未确认的交付要求继续保持未完成。

目标要求的初始语义提取仍可能受模型理解影响。验收必须覆盖错误提取、修订及最终目标核对，记录无法确认的要求，避免以结构化字段完整代替任务完成。

用户已选择在每个文档任务或多步骤任务结束前，由本地主模型进行一次原始目标核对。核对输入包含原始请求、已提交澄清答复、当前目标要求、实际覆盖和已发布文件。只有任务状态及成果发生变化时才重新核对，同一成果复用已保存的核对记录。

核对返回已满足、继续执行或需要补充信息。应用继续独立校验覆盖和文件完整性。模型可修正此前推断的目标，缩减用户已确认要求需要本任务的新答复。专业关键词提示尚未得到语义决定时，结束核对同时确定是否需要证据，并在需要时安排实际检索。

## 验收底线

全文审阅要求不会因只读取元数据而满足。读取后能够扩大计划范围。普通文件请求能进入首次模型动作。一个等待用户的任务允许其他任务登记恢复。更新计划和审阅之后的瞬态主模型故障能够继续当前阶段。模型与应用报告的完成状态能够用覆盖和实际文件核对。

# 意图识别恢复 文档处理与安装体验改造计划

> 实施时使用 superpowers:executing-plans，按任务完成回归和独立提交。

## 目标

让模型根据用户请求决定附件读取范围，在可解释、可取消的等待过程中完成识别，并支持整份适航模板分批填写。改善重排序和完整离线安装的耗时与进度反馈，完成新版交付。

## 设计依据

实施规格以用户在 2026 年 11 月 13 日确认的完整计划及后续补充为准。本文件记录其实施安排。

- 意图识别当前使用 30 秒共享截止时间，普通任务识别失败会阻断发送。
- 附件已有独立解析进程、Office 转换、PDF 与 OCR 流程。
- 应用托管的模板导出调用 `select_section`，一次定位一个位置。文档工具本身支持按稳定位置 ID 批量回填。
- 测试模板有 854 个正文段落、61 个表格，正文中的“试验目的”出现 14 次。
- 重排序最多使用 40 条候选。ONNX 请求按每批 2 条提交，每批当前有独立超时。
- 同设备的嵌入与重排序切换会回收 worker，产生重复校验和模型加载。
- 安装器在展开 `payload.json` 后进入长时间处理，中间阶段输出不足。本机 preview.2 安装约 30.4 分钟，卸载清理超过初始 6 分钟观察窗口。

## 架构与技术栈

在现有 Python Core、React/TypeScript、Rust/Tauri 和 NSIS/PowerShell 中实施。复用现有附件解析、模型调用、证据快照、文档回填、文件授权和任务审计。

将意图识别建为可恢复的任务，优先整合识别结果与首次读取决策。模型输出附件读取计划或工具调用，应用校验后执行既有解析器。整份模板按稳定字段 ID 和章节批次处理，生成结果通过应用管理的文档发布流程保存。

## 产品行为

### 意图识别等待与重试

- 默认单次尝试等待 90 秒，设置范围为 30 至 180 秒。
- 最多 3 次模型请求，包含首次调用。格式修复和兼容格式的重发也计入次数。
- 首次可恢复失败后最多自动重试一次。第三次尝试由用户点击触发。
- 默认同一识别任务的累计活动等待上限为 270 秒，用户查看提示和补充信息的时间单独记录。
- 用户提交澄清答复后形成同一任务的新修订，按修订重新计算识别预算，并隔离旧修订结果。
- 模型加载使用独立加载预算。每次识别的等待包含排队、输入处理和输出生成。
- 当前请求仍在运行时，“继续等待”延长其截止时间，仍受单次 180 秒和整轮 270 秒上限约束。
- 当前请求已经终止时，显示“重新尝试”。先确认旧请求取消和推理资源释放，再发起下一次。
- 取消、继续、重试及重启恢复复用任务身份和请求指纹，保存附件哈希、配置、次数与终止原因。
- 变更输入或附件后创建新的识别任务，旧任务结果根据任务身份隔离。

### 超时说明与澄清

- 意图澄清采用对话中的交互弹窗。弹窗显示已识别的任务、需要补齐的问题、建议选项和自由输入框，用户提交后恢复原任务。
- 一次优先询问一个影响下一步的问题，复杂任务可在同一弹窗组合少量相关问题。建议选项须由当前请求与附件状态产生，默认选项需要用户明确提交。
- 弹窗提供“确认并继续”和“取消本次任务”。用户主动关闭时保存等待状态，并在聊天中提供“继续补充”入口。
- 需求澄清使用“需要补充任务信息”弹窗，技术超时使用“识别等待超时”弹窗。超时弹窗展示已耗时、当前尝试次数、实际错误说明，以及符合任务预算的继续等待或重新尝试操作。
- 弹窗答复绑定原识别任务并保存审计记录，继承当前模型、项目、RAG 模式与附件身份。恢复后从待执行阶段继续。
- 任务只有在需要用户补充信息或决定下一步时进入弹窗。模型识别到已明确的整份填写、模拟数据和正文提取要求后，进入对应执行流程。
- 程序采集模型就绪状态、排队状态、耗时和真实错误码，形成可核验的诊断。
- 模型可用时，根据已授权请求和状态生成简短澄清。该调用受剩余请求次数和时间预算限制。
- 模型不可用时，程序展示诊断和具体操作入口。
- 请求缺少必要信息时，只询问下一步执行所需的一项信息。
- 用户已经提供的信息写入任务状态。完整模板、允许模拟参数等明确要求应直接进入规划。
- 显存不足、模型文件异常和依赖缺失进入配置处理入口，修正后允许用户重试。

### 模型驱动的附件读取

- 用户通过自然语言提出提取、分析或填写要求，由模型结合请求、附件清单和任务状态判断读取对象与范围。
- 模型先获得附件 ID、名称、类型、用途和大小等元数据。原文内容通过受权限和预算控制的附件读取工具逐步返回。
- 模型输出读取计划或工具调用，Core 检查附件归属、原件身份和读取范围后，调度现有解析、转换与 OCR 流程。
- 原生工具模型使用附件读取工具。纯文本模型使用经过结构校验的读取计划，由执行器完成相同操作。
- 解析结果按文件哈希和解析配置缓存，模型可按页、章节或片段继续读取。
- 意图识别超时进入既定的等待、重试和澄清弹窗流程，用户补充的信息合并到同一任务。
- 提取结果保存为可分页查看的产物，显示来源定位、覆盖范围和解析问题。
- 长附件按需读取片段，模型输入使用现有上下文预算。
- 提取、OCR、内容分析和文件生成显示各自的处理状态。

### 整份模板填写

- 支持整份填写和指定章节填写，保存范围及用户提供的设备资料。
- 以章节路径、段落和表格位置建立稳定字段清单，区分标题、说明、示例和填写目标。
- 同名“试验目的”由完整章节路径及字段 ID 定位。
- 允许模拟数据时，设备型号、参数与试验安排统一使用可追踪的模拟值，并在文件中标明示例用途。
- 条款号、标准版本、原文摘录和物理页码来自实际采用的证据。缺少依据或设备信息时记录待补充项。
- 按章节分批规划、检索、生成结构化字段结果，调用已有 `fill` 执行回填。
- 输出保留段落和表格布局，记录字段状态、证据、缺项和复核状态。
- 同一字段重试按任务和字段身份更新，已完成章节可恢复继续。
- 保存后验证文件身份、可打开性和目标路径，再报告完成。

### 重排序

- CPU 允许嵌入与重排序分别驻留，受可用内存预算控制，内存紧张时回收闲置模型。
- CUDA 使用设备资源预算和串行调度，显存错误显示具体模型、阶段与恢复入口。
- 普通检索先重排 20 条候选。完整分析与需要扩大范围的情况最多使用 40 条，所有扩展受整轮时间限制。
- 以现有 40 条路线建立条款命中基线，对照验证 20 条路线。发生质量回退时调整策略并记录原因。
- 重排序输入长度按实际 tokenizer 计算，评测 512、1024、2048 token 档位，选择满足条款命中基准的配置。
- 排序输入与证据正文分别管理。引用和原文展开继续从实际证据内容生成。
- 批次按长度和资源预算组织，保留内存不足时减小批量的恢复流程。
- 显示候选数、已处理数、模型加载耗时和计算耗时。
- 整轮重排序默认 90 秒，作为可调整初始值。到期保存检索候选，显示重试或用户明确选择的候选预览入口，回答发布继续执行证据与相关性检查。

### 安装与交付

- 安装界面显示校验分卷、解压组件、复制与校验、安装前置组件、发布完成等阶段。
- 各阶段使用实际计数或不定进度。只有全部发布成功才显示完成。
- 显示已耗时、目标目录和当前文件。阶段日志持续刷新，避免长时间停在 `payload.json`。
- 对清单读取、逐文件操作和重复读取进行计时，优先优化目录重复创建、重复遍历及可合并的流式哈希操作。
- 分卷、载荷身份、路径校验、事务发布和失败恢复需要通过回归。
- 完整安装与卸载观察实际进程树完成状态。验收脚本对 NSIS 临时卸载子进程提供足够观察时间。

先完成任务一和任务二，使等待可恢复、模型能自主选择并读取附件。随后实施整份模板流程，再完成重排序与安装器优化，最后进行集成验收和发布。每个任务形成独立、可验证的提交。

阶段一至五的功能代码和兼容回归已经实施，集成验收及发行状态见 `docs/interaction-recovery-acceptance.zh-CN.md`。主模型和辅助模型的可调驻留已通过真实模型测试。真实整份模板的最终发布与逐页检查仍待完成，当前机器的测试遇到辅助模型内存不足和重排序超时。原始模板作为本机业务测试资料管理。

## 用户追加的可调模型驻留

- 主对话模型、嵌入和重排序模型均支持可调空闲驻留。
- 主模型和辅助模型分别设置，默认均为 30 分钟。
- 界面提供 5、15、30、60 分钟、自定义 1 至 1440 分钟，以及手动卸载。
- 配置使用秒持久化，0 表示关闭空闲自动卸载，其他值范围为 60 至 86400。
- 设置修改立即生效并重新开始空闲计时。活动生成、已固定任务和推理中的辅助模型受保护。
- 辅助模型继续受内存预留、最多两个 CPU 驻留模型和 CUDA 资源协调约束。
- 推理成功结束时更新最后使用时间，应用退出、设备更改及完整性异常沿用进程回收流程。

## 完整包差异安装的实施补充

- 原生安装助手比较受管文件身份，只展开包含变化文件的分卷，校验通过的现有文件直接复用。
- 分卷映射记录在清单中，同目录旧分卷按大小和 SHA-256 识别。
- 同盘备份和持久化事务记录覆盖新增、替换、受管删除及回滚。未知文件保留或隔离，并显示记录。
- 安装后握手使用独立临时数据目录，正式业务数据库在实际启动时按备份迁移。
- 安装及卸载辅助子进程受 Windows Job Object 管理，恢复先确认子进程结束。
- 卸载保留可重试的受管清单，所有可失败清理完成后进入安装器的成功收尾。

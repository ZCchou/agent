# PDF 自动 OCR 与表格识别接入 RAG 完整修改计划

> 执行说明。实施时使用 superpowers:executing-plans 按任务执行。各任务使用复选框跟踪，先复现测试失败，再实现并验证。

**目标**

用户导入 PDF 后，应用自动完成文本检测、按需 OCR、表格结构识别和 RAG 入库。默认流程自动接受可处理结果、标记异常区域，提供逐页恢复和按需校核。回答可以定位回原件页码及识别区域。

**架构**

沿用现有 Python Core、SQLite、文件授权、RAG、后台任务及受管进程机制。增加独立 OCR 运行组件和有界并发流水线，按设备能力选择已验证的 CUDA 或 CPU 后端。文字识别、版面分析、表格结构识别分别采用固定适配模型，通过受管本地模型包加载。

**技术栈**

Windows 11 x64、Python、PaddleOCR 系列及匹配的 Paddle CPU/CUDA 推理组件、pypdfium2、SQLite、React、TypeScript、Tauri。主模型及现有嵌入、重排序模型继续通过既有接口参与问答和检索。

**需求依据**

本会话已讨论的自动 OCR、离线运行、本地模型文件配置、表格校核及证据追溯要求。本文第 1—9 节同时作为本轮设计规格，第 10—12 节作为实施和验收计划。具体模型发布版本、依赖锁与资源预算属于本计划提出的实施选择，需要通过第一阶段实测固定。

2026-11-09 易用性修订采用自动入库为默认流程。常规 OCR 和表格识别使用成熟流水线，人工校核集中于疑点。设备选择、并发度和资源预算自适应，页面级进度与检查点独立于执行并发。逐项校核作为可选策略，资源参数作为经过实测的可调整配置。

## 1. 基线与问题

- 仓库为 `ZCchou/agent`，本地基线提交为 `78548d9`。
- 当前数据库 schema 为 25，IPC 为 18，构建标识为 `schema25-local-runtime-v1`。
- PDF 使用 pypdfium2 提取文本，以整页文本作为源块，再切分为片段。
- 当前解析可以保留物理页码，对图片文字、图片表格和曲线中的数值缺少有效提取能力。
- 当前文档确认依赖整份文档的警告确认，缺少区域级审阅、修订和排除记录。
- 当前解析进程单任务内存上限为 1 GiB，整份文档超时为 125 秒。现有整文档解析接口需要增加分阶段调度，避免将长文档 OCR 放入该限制中。
- 当前索引与项目绑定已有版本快照、资料变更序号及原子发布机制，可以作为新流程的发布边界。

DO-160G 本机试解析结果为 542 页、约 13.1 MiB、981 个片段。物理第 31 页的印刷页码为 4-9，包含 Table 4-1 图片表格，现有解析未取得该页文字。该文件作为本机验收样本，原件及整页截图仅保存在本机测试资料中。

## 2. 本期范围及默认行为

### 2.1 交付能力

1. 文本 PDF、扫描 PDF、文本与图片混合 PDF 的自动识别。
2. 中英文印刷文字、页面方向、区域方向和基础倾斜处理。
3. 表格检测、行列恢复、合并单元格、表头及脚注关联。
4. 原件与识别结果对照预览、人工修订和审阅记录。
5. 导入后按需识别，自动形成可检索快照，校核结果按新快照更新。
6. 逐页进度、取消、失败页重试和重启恢复。
7. 模型文件导入、运行组件校验与完整离线交付。
8. OCR 证据来源、置信度、校核状态和原图区域追溯。

复杂图形、手写内容、数学公式及曲线读数单独显示识别质量和资料缺口。成功提取的可读内容可以进入检索。无法可靠恢复的结构保留原图引用，并提供重试或人工补充入口，其他区域继续处理和入库。

继续执行现有输入 100 MiB、提取文本 2,000 万字符、资料库累计 10 万片段和解析结果 256 MiB 的限制。OCR 中间文件与解析结果分别计量，二者都必须通过上限检查。

### 2.3 方案选择

基础 OCR 可以补齐扫描文字，完整 OCR 与表格识别还可以恢复单元格与表头的关系。本计划采用后者，以 DO-160G 中的类别、限值、单位和脚注关联作为首批验收重点。

OCR 提供 CPU 通用后端和经过验证的 NVIDIA CUDA 后端，自动选择结果在界面展示。OCR 所需运行组件、模型及适配规则均通过受管本地文件加载。与主模型、RAG 共享 GPU 时通过既有资源协调器安排加载和推理，在显存不足时采用自动模式的 CPU 路线并显示实际设备。手动指定设备失败时保留具体错误和切换入口。

## 3. 模型与运行组件

### 3.1 适配模型包

第一阶段评估并固定以下模型角色。

| 角色 | 候选来源与选择规则 |
|---|---|
| 文字检测与识别 | PaddleOCR PP-OCRv5 mobile 系列，优先选择官方中英文适配组合 |
| 页面与文字方向 | 与上述推理组件兼容的官方方向模型 |
| 版面分析 | PaddleOCR 官方版面模型，必须覆盖正文、标题、表格、图片和脚注区域 |
| 表格结构 | 与版面模型配套的官方表格模型，包含有线表和无线表适配 |

发布前固定每个模型的官方下载来源、精确 revision 或发布资产版本、全部文件 SHA-256、许可证、输入预处理、输出坐标约定和后处理版本。第一阶段产出可复现的兼容性报告，后续阶段只接受该报告锁定的组合。

采用独立 OCR 模型包，例如 `ocr-model.json`，记录角色、适配器、文件清单、哈希、语言、运行组件身份及版本。OCR 模型目录管理与现有 embedding/reranker 角色校验分开，复用文件授权、暂存复制和原子登记流程。

导入过程检查目录穿越、链接与 junction、缺失文件、损坏模型、包大小和磁盘空间。受管加载只使用清单中的文件，执行路径由应用内置适配器决定。模型包无法提供 Python 脚本或可执行插件入口。

### 3.2 离线交付

- OCR CPU 运行组件随离线包提供。CUDA 组件以匹配版本的本地离线载荷提供，使用独立 DLL 搜索路径，并与 CPU-only 电脑兼容性分别验收。
- 默认模型通过本地模型包导入。离线交付 ZIP 可以附带经过许可证核验的默认模型包，并从随包目录完成本地校验和登记。
- 应用启动时显示组件可用性、模型可用性和完整性状态。
- 缺少 OCR 组件或模型时，导入任务显示具体原因及本地导入入口。原有可读文本形成部分收录快照并可检索，尚未识别的区域持续显示为资料缺口；用户补充组件后可以继续识别。
- OCR 模型加载、组件初始化和故障恢复全部通过应用托管流程完成。

## 4. 自动导入与识别流水线

### 4.1 导入流程

文件授权选择并确认一次导入设置 → 原件受管复制与哈希 → 页面检测与原生文本提取 → 按需 OCR 和表格识别 → 区域合并与去重 → 条款和表格整理 → 自动形成可用快照 → 建立索引并按导入授权应用到项目。用户可以随时打开预览处理疑点，修订后生成新的索引快照。

普通导入和批量导入均调用同一流水线。导入主界面默认只显示文件、目标资料库及“导入并建立索引”。OCR 模式、指定页码、发布策略和本项目自动采用选项放入可展开的高级设置，并保存到任务快照。已有文本 PDF 的可用正文可以先发布一个初始快照；完整扫描件在首批 10 个可用页面处理完成后可以形成初始快照。每次导入最多自动产生一个初始快照和一个完整处理快照，避免频繁重建索引。疑点数量显示在任务和资料卡上。

### 4.2 逐页判断

综合使用文本覆盖区域、图像区域、字符映射异常、阅读顺序及版面模型结果判断。

- 有可靠文本的正文区域使用原生提取。
- 无可靠文本的扫描区域触发 OCR。
- 只有页眉页脚文字、正文主要是图片的页面触发 OCR。
- 表格检测覆盖图片表格和具有文本层的复杂表格。
- 图表和公式区域保留原图及可读文字，结构不确定时显示疑点标记，提供可选校核入口。
- 对空白页记录空白判定及依据，预览中可以人工纠正。

检测依据与处理决策保存到页面记录。用户可以重新指定页面强制识别。

### 4.3 合并与去重

- 使用原生文本和 OCR 的区域重叠、文字相似度及阅读顺序判定重复。
- 重复区域保留优先来源和备选识别结果，便于核对。
- 表格占用区域生成表格内容块，避免再次作为散乱正文进入索引。
- 页眉、页脚及重复版权文字保留原文定位，按识别规则从检索正文中分离。
- 跨页条款保存连续关系。跨页表格在表头、列结构及上下文一致时自动关联；关联冲突时保留各页结果并提示校核。
- 相同条款号在目录、正文、附录中分别记录所属章节，精确检索优先使用已确认正文。

### 4.4 表格表示

同时保存表格原图区域、原始识别文本、结构化单元格和检索用文本。

单元格至少包含表格 ID、行列号、跨行跨列范围、表头路径、原文、单位、脚注关联、坐标和识别置信度。检索用文本展开表头与字段关系，例如“文件版本、表格编号、设备类别、试验条件、数值、单位、关联脚注”，具体值从结构可用的识别结果或人工修订结果生成，并携带来源及校核状态。

负号、小数点、范围符号、上下标和单位保留原始字符串。单位换算或其他专业推导如需加入，应另行记录推导依据及人工复核结果。

整表、逻辑行和脚注建立父子关系。索引以可读的逻辑行或条件组合为检索单元，原文展开能够取得所属表头、适用条件及关联脚注。长表保留分段关系。

## 5. 校核与发布规则

### 5.1 状态与置信度

区域状态使用 `pending_review`、`accepted`、`corrected`、`excluded`。

置信度保存到文字和结构层级。模型原始分数及应用校准结果分别记录，评分用于安排校核优先级。阈值在标注集上校准后随适配器发布。

可读且通过结构检查的正文及表格区域可由规则标记为 `accepted`，记录规则身份与自动接受原因，并展示“机器识别”。`accepted` 表示准予入库，人工校核身份单独记录。温度、海拔等数值内容按识别与结构质量安排疑点，成功识别的表格可以自动入库。

以下情况优先提示校核。

- 关键试验限值、类别及单位存在字符歧义或行列表头冲突的表格。
- 低置信度、识别冲突、明显乱码和阅读顺序异常。
- 缺失脚注、合并单元格不确定、跨页表格和跨页引用不确定。
- 公式、曲线读数、图中说明和手写内容。
- OCR 失败、超时或因为资源不足跳过的区域。

### 5.2 默认入库与可选校核

默认采用自动入库。识别分数用于安排疑点和检索质量标记，文字与表格结构共同参与判断。保留“逐项校核后入库”策略供用户选择，其校核条件由 Core 执行。

自动模式在存在可读内容且数据格式、来源身份、范围权限及快照一致性通过检查时形成可用版本。低置信度内容可以带疑点标记作为参考文字参与检索。结构无法确定的表格保留原始识别文字与原图入口，结构化数值字段只来自可确定的行列关系。完全不可读区域暂不生成文本证据，并在覆盖报告记录原因。其他区域持续处理，局部异常通过局部重试解决。

覆盖报告自动记录尚未处理、失败和不可读区域，资料标记为“部分可检索”或“可检索，有疑点”。用户可以稍后修订或排除区域，人工排除时记录原因。回答上下文携带覆盖及质量标记，涉及歧义数值的结果展示原文入口和核对提示。

同一可用快照执行事务性发布，后续处理及修订形成新快照。逐项校核策略在待校核区域全部处理后发布。入库状态、人工校核状态和业务文件适用版本状态分别展示，并继续执行项目原有的版本与适用范围规则。

文件名和本地导入来源自动填充。文件编号及版本优先从文档提取，推断值标注“自动识别”，未取得的值记录“未标注”及元数据状态，后续可以补充。已确定的适用版本过滤继续按明确版本值执行。普通文档检索可以展示元数据缺口。

### 5.3 自动建索引

默认在可用快照形成后自动创建 `index.build` 任务。人工校核和完成 OCR 后的完整快照可以继续触发更新。索引建立失败显示独立任务状态，已有可用快照继续保留，可重新建索引。

自动构建以当前资料库已发布索引的明确版本集合为基础，加入本次新确认版本，并替换同一来源族的旧解析版本。整个候选集合保存为任务快照。同一来源族在单个候选索引中最多选择一个解析版本。

资料确认与索引排队分开提交。资料库已有索引任务时，后续确认更新持久化的待构建集合，按库串行、合并安排下一任务。资料变更导致当前构建过期时，任务显示过期并根据最新集合重新构建，最后发布前继续校验版本集合和资料库变更序号。任务创建失败时显示可重试的排队状态，已确认资料可以继续预览。

导入目标为当前项目时，在一次导入操作中明确展示“自动采用本次导入结果”，授权范围限于本任务及该项目。选中后可以自动采用初始和完整快照。固定旧索引的项目保留手动采用入口，其他项目绑定按各自策略执行。后台自动导入和 OCR 均使用已授权范围，运行中的回答继续执行变更序号检查。

## 6. 进程、资源、恢复与缓存

### 6.1 进程隔离

- 现有解析进程承担受限的原生文本提取和页面检测阶段。
- OCR 使用独立受管 worker，通过 Windows Job Object 限制内存和回收进程树。
- 页面检测、渲染、OCR 和结果写入通过有界队列连接，输出页级结果并及时提交检查点，避免整份文档常驻内存。逐页记录可以与并行执行配合。
- CPU 默认自动选择 1—2 个 worker，总线程预算按物理核心数及界面响应余量分配，按实测 worker 内存峰值核对可用内存。资源不足时降低并发，正常任务由队列继续推进。
- CUDA 使用单个推理 worker 和经过验收的有界批量。复用已加载模型和预处理缓存，限制预取图像数量，与主模型及辅助模型协调显存。渲染和存储阶段可以同时推进。
- OCR 资源预算使用独立配置。新配置经校验后进入 frozen Core，保留生产环境禁用任意命令覆盖的限制。
- 任务调度器逐页检查取消与资料状态，页面超时终止对应 worker，完成页继续保留。
- OCR 单页超时、模型启动超时与整份文档排队时间分别记录。整份 542 页文档使用页级调度和持久进度。
- 资源检查分为模型组合支持边界和运行时调度。优先降低并发、批量和预取数量，自动设备模式可以切换 CPU 并展示原因，降级后仍不足才暂停。用户可以在经过验证的范围内调整内存预算和任务优先级。

### 6.2 结果协议

定义带协议版本和 `request_id` 的 OCR 请求及状态帧。内容通过受管暂存文件传递，日志仅记录版本、页码、耗时和错误码。

Core 校验结果文件身份、哈希、字节上限、页码、区域数量、坐标边界、有限数值置信度、表格索引、文本长度及所属任务。无效结果无法进入正式资料版本。

### 6.3 恢复与缓存

缓存身份包含原件哈希、物理页码、渲染及预处理配置、适配器版本和全部模型指纹。缓存结果按项目资料授权读取，文件哈希和完整状态通过校验后才能复用。

完成页使用原子写入并提交检查点。重启后将未完成任务标记为中断，用户选择恢复后，从经过校验的完成页继续。失败页支持单独重试，成功页保持复用。

人工修订作为独立草稿覆盖层保存，重新 OCR 生成新的解析草稿，并展示与已有修订的差异。已确认内容保留可追溯快照。

清理仅作用于受管、带所有权标记的缓存和暂存文件，先核对运行占用。原件、已发布证据依赖和审计记录遵循资料保存规则。

## 7. 数据、版本与证据定位

### 7.1 数据迁移

数据库从 schema 25 升至 26，新增以下表。

| 表 | 用途 |
|---|---|
| `rag_parse_runs` | 原件、OCR 模式、配置和模型指纹、处理阶段、任务关联 |
| `rag_page_results` | 页码、页面尺寸、旋转、文本覆盖、状态、检查点和结果哈希 |
| `rag_regions` | 区域类型、原始及修订文本、坐标、置信度、阅读顺序、校核状态 |
| `rag_table_cells` | 表格行列、跨行跨列、表头、单位、脚注及单元格定位 |
| `rag_review_events` | 修订前后哈希、操作者、时间、原因和乐观锁版本 |

`rag_versions` 增加 `source_family_id`、`derived_from_version_id`、`parse_run_id`、`coverage_status`、`review_revision`、`release_policy`、`assurance_status`、`metadata_status` 和入库快照哈希。`rag_jobs` 增加处理阶段、完成页数、总页数、关联版本及任务参数快照。页面处理修订和人工修订分别计数，后台处理其他页面时可以继续保存当前区域的人工修订；发布快照同时冻结两者身份。

迁移将已有资料版本各自设为独立来源族，保留现有状态、片段 ID、文本哈希、索引及项目绑定。原有定位中缺少 OCR 字段时，按旧版文本证据展示。

### 7.2 草稿与不可变版本

- 原件保存后创建零片段的 `pending` 草稿版本和解析任务记录，原件继续采用既有受管哈希存储。
- 页面解析及校核结果写入草稿区域记录，最终由同一事务生成对应片段、全文索引词项和确认快照。
- 人工保存和人工确认都提交 `expected_revision`，自动发布使用任务快照的对应修订号，过期请求返回冲突并重新排队。
- 已确认版本的文字、单元格和定位保持不可变。重新识别或修订创建派生版本，继承来源族并记录父版本。
- 派生版本沿用业务文件编号与修订版，解析运行版本单独展示。导入新的业务修订版建立新的来源族。
- 文档撤回作用于同一来源族的全部解析派生版本，并更新资料库及项目变更序号，阻止旧证据继续使用。
- 候选索引包含所选版本 ID、确认快照哈希、切分策略和模型指纹。发布时重新校验这些身份及变更序号。
- 同一来源族的多个解析版本可保留用于审计和历史引用，单个索引中的来源族选择执行唯一性检查。

### 7.3 定位与引用

OCR 区域保留物理页码、原 PDF 页面尺寸、CropBox、旋转、模型输入变换及映射回原页的四边形坐标。PDF 原生坐标单位使用 point，前端通过统一变换适配旋转及显示缩放。

证据至少增加 `extraction_method`、`parse_run_id`、`region_id`、`table_id`、`cell_ids`、`review_status`、`review_digest` 和坐标。印刷页码作为独立、可校核字段保存，和物理页码共同展示。

`rag.search` 与 `rag.read` 继续使用现有只读工具和项目范围。读取表格证据时返回关联表头、条件和脚注，控制在既有上下文预算内；超预算时明确返回截断及继续读取范围。

引用点击后打开原 PDF 对应页面并高亮区域。区域渲染同样检查项目权限和当前撤回状态。修改过的文字展示“人工修订”，引用校验核对实际进入上下文的已确认快照。

# RAG 修复与 Office/WPS 附件读取实施计划

用户已要求先修复 RAG，并接入 Office、WPS、PDF 和 OCR 附件读取。本计划在现有 OCR 预览 worktree 执行，保持已发布版本可独立使用。

## 目标与边界

复用现有文档解析进程、OCR worker、附件快照和证据校验。附件原件保持不可变，模型读取带来源位置的文本衍生物。宏和外部链接不执行。密码、损坏、缺失转换器及 OCR 未配置均报告明确状态。

Office/WPS 按实际容器识别，OOXML 文字、表格和幻灯片直接解析。旧二进制、RTF 和 WPS 原生格式通过受管本地转换组件转为可解析格式，验证兼容性后声明可用。转换进程设置超时、取消和资源回收。

## 任务

- [x] 1. RAG 回归修复。先写失败测试，覆盖翻译和解释追问的原文重新授权、空片段排除、PDF Section 章节重置、重试证据身份及引用失败诊断。保持跨项目、版本撤回、原文摘录约束。
- [x] 2. 文档格式读取。新增 Office/WPS 格式注册与转换适配，解析 Word 段落、工作表单元格、幻灯片和来源位置。补充压缩包、加密、损坏和真实模板测试。
- [x] 3. 对话附件接入。原生选择器及拖拽接受文档，Core 在生成前异步提取受管原件，PDF 自动 OCR，保存校验过的 UTF-8 衍生物并接入现有附件引用及预算流程。大文件保留范围读取，禁止无声截断。
- [x] 4. 集成验证与交付。运行 Python、前端、Rust 和契约回归，实际读取用户提供的 DOCX 与 PDF。记录各格式、OCR 与转换器真实验收状态，构建隔离试用版本。

## 验收重点

上一轮原文可用于翻译且生成新的本轮证据授权。纯分隔符不会成为证据。第 16 节不会继承第 14 节归属。附件可经正常导入与发送入口被纯文本模型读取，保留页码、工作表或幻灯片位置。取消和失败不得留下可误用的半成品。旧对话、复制及历史附件引用继续可用。

## 本轮验证结果

Core 完整回归 1,161 项通过，最终 RAG 与文档专项 127 项通过。前端 188 项通过，TypeScript 检查通过。Rust 261 项通过，2 项忽略。真实 DOC、XLS、PPT、RTF 及 Word 模板转换通过，DO-160G 第 31 页附件 OCR 和第 161 页章节归属通过。冻结 Core 的 Office 子进程解析通过。独立 Document Preview 已启动且 Core 在线，用户 Word 模板经原生选择器进入聊天附件。

WPS 原生旧二进制格式仍缺真实样本，转换进程尚无操作系统级网络隔离。长文档默认按问题选段，显式范围保留完整性和预算检查。新预览采用独立数据目录，首次需要配置主模型与辅助模型。

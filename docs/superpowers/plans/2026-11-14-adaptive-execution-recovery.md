# 对话与 RAG 持续等待与故障恢复实施计划

本计划实施用户已批准的全链路方案，以 0.16.0-preview.4 为基线，目标 0.16.0-preview.5。

## 产品要求

- 覆盖主模型加载、意图识别、附件读取、转换与 OCR、嵌入、重排序、模板审阅及生成。
- 智能等待为默认。90 秒提醒，300 秒无进展进入诊断，阈值可配置 60～3600 秒。每 5 秒心跳和资源采样，30 秒心跳失联进入诊断。智能等待总时长不限，自定义总时长为 1～1440 分钟或不限。
- 存活、实际进展、资源活动和队列状态分别记录，未知监控数据保持未知。资源等待单独计时。有真实进展或执行活动时继续执行。
- 确认进程退出，或两次相隔 30 秒诊断均确认通信失联且无活动，进入恢复。证据不足时保留进程并等待用户确认。
- 同一阶段连续无进展失败自动恢复两次，仍失败暂停。用户可以多次手动恢复。通过校验的新批次或阶段结果清零连续恢复计数，历史尝试保留。格式纠正每阶段最多三次实际调用。
- 活动任务固定模型使用权，调用结束后开始驻留倒计时。
- 控制请求快速返回身份，业务运行通过事件与查询更新。超时控制请求先查询原任务状态。
- 重排序保留实际 tokenizer 长度分组、2048 token 输入预算及全部候选，内存不足降低批量至一条。每批评分校验后事务保存。
- 检查点包含项目、任务修订、查询、检索范围、资料变更序号、索引/版本身份、候选顺序/文本哈希、模型/设备/配置身份和评分。恢复先校验身份。结束后保留 30 天，明确删除业务记录时联动清理。
- 确认旧请求与进程结束后恢复。写入及终端操作复用授权、幂等和结果核验。重启后任务显示中断，由用户恢复。睡眠唤醒重新检查活动与计时。
- 模板非空内容审阅建立稳定段落/单元格 ID、章节路径、正文/说明/示例/已填分类，按章节每批最多十目标并受上下文约束，逐批读取、检索、校验和保存。报告覆盖数量、问题、证据、版本差异和缺项，所有目标得到结果或明确待处理状态后发布。
- 资料为外部输入，授权、证据检查、人工复核继续贯穿执行。权限/模型损坏/依赖异常展示配置入口。证据变化重新检索。内存不足降低批量/释放空闲模型。
- 错误保留原业务码，按任务/尝试/故障事件去重。自动恢复更新同一卡片，检索异常通过应用诊断处理。

## 界面与契约

- 聊天使用持续状态卡，显示阶段、模型/设备、完成数、耗时、最近进展、等待原因和恢复次数，提供详情、取消、继续等待、恢复和配置入口。
- 模型设置集中提供运行与等待。全局策略作用于新任务，当前任务通过单独控制修改。
- execution.request 支持查询、继续等待、重试当前阶段、取消，携带任务 ID、revision 和幂等标识。意图转入运行绑定同一根任务。迟到事件按身份过滤，终态通过事务唯一决定。
- schema 32、IPC 25、设置 schema 20、build ID schema32-agent-unified-v1、worker 协议 v2、工具契约 v5。迁移启用智能等待，旧时限留作自定义参考。备份并核验历史资料、对话、索引及附件。
- 重建变更的推理/解析 worker，通过完整离线差异安装交付，校验一致的分卷复用，更新器识别组件兼容性。

## 验收重点

超过 90/300 秒仍推进的任务完成。仅心跳无进展触发诊断。两次无进展恢复后暂停。取消/完成/恢复得到唯一终态。重启、睡眠、模型/资料变化正确处理。读取权限/内存/依赖错误明确。活动模型驻留正确。完整审阅覆盖清单可核对。

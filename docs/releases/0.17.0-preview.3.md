# 0.17.0-preview.3

## 任务目标与完成核对

- 单独保存原始请求、澄清答复及目标要求。执行计划支持读取后扩展资料范围，分别记录读取和审阅结果。
- 文档及多步骤任务结束前，本地主模型核对原始要求和实际成果。应用同时核对必需范围、文件格式、实际交付位置及 SHA-256。
- 核对输入包含经过哈希核验的文档正文，省略范围带有明确标记。未满足的事项继续处理，需要用户信息时进入原澄清流程。
- 模型可以修正推断出的要求。用户已确认的范围、文件路径和完成条件由独立确认记录保护，变更时需要本任务的新答复。
- Word 正文需要纠正时，重新生成并发布文件，随后再次核对。文件别名按实际交付身份合并计数。

## 分流与恢复

- 自动模式中的专业关键词作为模型提示。项目启用资料库后，模型可以先采取实际动作，并按任务语义选择检索。
- 强制 RAG、Skill 的明确要求及已确认的证据义务继续生效。模型选择检索后，后续回答自动接入证据输出约定。
- 启动时分别登记中断任务，等待用户答复的任务释放主模型占用。恢复识别时，模型准备和执行占用连续衔接。
- 本地托管模型及本地 HTTP 模型在当前调用尚未输出时恢复该调用，复用已完成工具结果。连续恢复次数沿用阶段策略。
- 模板审阅的完成纠正继续处理原先选定的附件。任务详情保留覆盖情况、交付结果和完成核对记录。

## 兼容

- Core 数据库 schema 35，IPC 28，工具契约 v7。
- 构建身份为 `schema35-agent-unified-v1`。
- 设置 schema 20，辅助 worker 协议 v2。
- 升级使用现有数据库、配置及程序备份机制。
